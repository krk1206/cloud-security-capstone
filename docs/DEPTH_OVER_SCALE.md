# 다른 조보다 "작아 보인다" 는 걱정에 대한 답 — 깊이로 이기는 계획 (2026-09-22)

B: "다른 조 프로젝트가 스케일이 더 커 보인다. 우리가 제일 낮은 느낌. 주제는 안 바꾸고 더 쩌는 퀄리티로, '미쳤다' 소리 나올 것들을 구현해 달라."

## 1. 결론

스택을 늘리면 진다. 다른 조 게시판의 **교수 댓글**을 보면 무엇이 점수인지 보인다:

| 조 | 겉으로 보이는 규모 | 교수 댓글 (원문 요지) |
|---|---|---|
| 3조 AI-SOC (OpenStack HA, 허니팟, 3개 에이전트, 대시보드) | 가장 큼 | "장애 대응 시나리오를 풍부하고 가시화되게", "구현 결과물은?", "성능 병목" |
| 4조 K8s 공방 (Falco, 권한 분리 109항목, 카탈로그 14) | 큼 | "이것만 한다면 **너무 단순하고 교훈이 없음**", "구현의 결과물은?", "**본인이 이해 못한 내용을 AI 가 주는 대로 발표 자료를 만들었음**", "제목 명확히" |
| 2조 문서 생성 모델 (Qwen 27B 파인튜닝 + RAG) | 큼 | "좋은 도구 알아볼 것", "파인튜닝 데이터 생성", "권한 아키텍처 study" — 아직 계획 단계 |
| 6조 MCP Agentic SOC (Qwen3-30B QLoRA) | 큼 | "랜섬웨어 실시간 대응은?", "에이전트가 속도를 따라가나?", "MCP 로 더 나은 점은?", "에이전트가 일으키는 문제" |
| 5조 온톨로지 RAG | 중 | "OpenStack 구축 중" — 뒤처짐 |

공통점: **크게 벌인 조일수록 "결과물이 뭐냐", "네가 이해하냐", "단순하다" 를 듣는다.** 교수가 우리에게 한 말도 같은 축이다 — "8계층 근거", "직접 쓰고 교정만", "남는 것", "AI 가 만든 건 공격받기 쉬운 지점".

그러니 "미쳤다" 는 규모가 아니라 **아무도 반박 못 하는 실측**에서 나온다. 우리는 이미 그 축에 있다: 실제 plan 37개에서 스캐너 사각 13건, 교차검증으로 자기 버그 7종 공개, 한 번 클릭 재현. 오늘 거기에 두 개를 더 얹었다.

## 2. 오늘 얹은 것 (전부 실측, 전부 재현 가능)

### 2.1 스캐너 사각 탐색기 — "Trivy 를 속이는 겉모습을 기계가 찾는다"

`scripts/fuzz_scanner.py` (`src/iacpatch/fuzz/`): 뜻은 같고 겉모습만 다른 Terraform 변형을 **자동 생성**해 Trivy 와 오라클(V6)에 나란히 넣는다. 정답은 변형을 만들 때 구조적으로 정해진다(0.0.0.0/0 을 64 조각으로 나눠도 합집합은 전체) → 사람 라벨 없음.

- SG 42종 (CIDR 분할 2~64조각·겹침·불균등, 별도 규칙 리소스 신·구, 변수/locals/함수 경유, dynamic/for_each/count, prefix list, SG 참조/self, 포트 범위/프로토콜, IPv6, 인접 SG 합산, 정상 수정 8종)
- IAM 32종 (`*`/`s3:Get*`/`S3:*`, Resource `*`/버킷 전체/접두 매치, 나열, 두 문/두 정책/인라인, heredoc/data source/Version 2008/객체형 Statement/locals, NotAction/Condition/Deny/관리형/NotResource, 필수 권한 누락, 신뢰 정책 `*`)
- 결과는 `experiments/FUZZ_RESULTS.md` (숫자는 그 파일이 원본; 아래는 1회차 실측, 샌드박스 Trivy 0.74.0):
  **잡혀야 하는 변형 59종 중 Trivy 사각 44종 → 오라클이 44종 전부 탐지, 놓친 것 0.** 정상 수정 10종 오라클 오탐 0. Tier 1 밖 구조 5종은 UNKNOWN 4 + 보수적 FAIL 1 (PASS 로 샌 것 0). Trivy 오탐 1(UDP 22 를 SSH 로 봄 — 프로토콜을 안 본다).

교수 질문 "이 정도에 자동화 도구까지 필요한가?" 의 답이 이 표다: 스캐너가 못 보는 겉모습이 **44종**이고, 그중 어느 것도 사람이 diff 만 보고는 못 잡는다.

### 2.2 오라클 차등 검증 — "오라클이 맞다는 걸 무작위 2만 건으로 보인다"

`scripts/oracle_fuzz.py`: SG 오라클의 CIDR 집합 연산(합집합·차집합·포함·전체 개방)을 **정수 구간으로 따로 짠 기준 구현**과 무작위 CIDR 목록 20,000건(IPv6 6,043건 포함)으로 대조, IAM 글롭 포함(`pattern_subset`)을 전수 나열 기준과 2,014건 대조. **불일치 0** (`experiments/ORACLE_FUZZ.md`, seed 고정, 누구나 재실행).

교수 질문 "V6 가 틀리면?" 에 "사람이 7종 찾았고(교차검증), 기계가 2만 건 대조했다" 로 답한다.

### 2.3 한 번 클릭 + 리포트 (이미 전달)

`IaCPatch.bat`/exe → 단위 테스트 → 실험 8단계(위 두 실험 포함) → `report/index.html` (핵심 숫자·깔때기·어느 계층이 잡았나·세트 표·근거 펼치기). 후보당 3~4분이던 팀 PC 실행을 provider 템플릿·원본 캐시·기록 재사용으로 줄였다.

## 3. "미쳤다" 소리를 내는 건 이제 사람 손에 달린 3개

기계로 더 만드는 것보다 이 셋이 훨씬 크다. 남은 9주에서 순서대로:

1. **AWS 에서 실제로 한 바퀴** (A, 10월 초까지): 취약 SG 배포 → 후보 → 게이트 → PR → 승인 → apply → `iacpatch postdeploy --execute`(V7 `describe-security-groups` 실측) → V8 접속 검증. 리포트 머리의 "AWS 배포 후 검증 0회" 가 1회가 되는 순간 이야기가 닫힌다. 다른 조는 아무도 "끝까지 닫힌" 시연이 없다.
2. **LLM 후보 36개** (B, 이번 주~다음 주): Claude Code 새 세션 × 고정 프롬프트. 지금 리포트에 "LLM 후보 0 (미측정)" 이 빨갛게 찍혀 있다. 이게 채워지면 "AI 패치의 몇 %가 스캐너를 통과하면서 실제로는 안 고쳤나" 를 **우리 실측**으로 말할 수 있다 — TerraProbe 인용이 아니라.
3. **각자 자기 계층을 자기 말로** (A·B·C, `docs/walkthroughs/`): 4조가 깨진 지점. 8계층 근거(`docs/WHY_8_LAYERS.md`)와 이 문서의 숫자를 안 보고 말할 수 있어야 한다.

그 다음(10월 중): S3 세 번째 유형, PR 봇(Actions required check + 검증 표 댓글) — 코드 골격은 준비하되 첫 실행은 push 뒤.

## 4. 하지 않을 것 (그리고 왜)

- OpenStack/K8s/EKS/컨테이너 CVE — 연구 질문(패치 실효성)과 무관. 4조·3조 댓글이 증거.
- 모델 파인튜닝·DGX — 우리 질문은 "AI 가 얼마나 잘 고치나" 가 아니라 "AI 가 고친 걸 어떻게 믿나". 모델을 키워도 답이 안 바뀐다.
- 대시보드/실시간 관제 UI — 리포트 한 장이면 심사에 충분. UI 는 판정 코드가 아니다.
- "AI 가 자율적으로 apply" — 우리가 하지 않기로 한 것이 곧 주장이다 (사람 승인 없는 apply 금지).

## 5. 발표 첫 장에 쓸 문장 (초안)

"겉모습만 바꾼 Terraform 패치 59종을 만들었더니 Trivy 는 44종을 통과시켰고, 그 44종은 전부 실제로는 인터넷에 열려 있거나 권한이 남아 있었다. 우리는 그것을 기계로 찾고, 기계로 막고(44/44), 그 기계가 맞는지를 다시 기계로 2만 번 확인했다. 실제 AWS 에서 한 바퀴 돌린 기록과 함께." — 마지막 절은 A 의 실측 뒤에 넣는다. 그 전엔 쓰지 않는다.
