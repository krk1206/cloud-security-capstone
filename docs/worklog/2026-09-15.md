## 설계에서 정한 것

- **파일 입력 원칙**: `review` 는 trivy/terraform/aws/LLM 을 실행하지 않는다. A 의 결과는 JSON 파일로 받고, 없으면 NOT_RUN(검증 대기)이며 PASS 를 만들어내지 않는다.
- **중복 finding 은 멈춘다**: A 의 PR #1 사본(`scenarios/dev/pr1-two-defects`)이 실제 사례(0107 ×2). `pipeline.select_target` 도 같은 규칙으로 고침.
- **스캔-원본 정합**: Trivy 의 원인 줄 내용과 원본 줄을 비교. 완전 확인은 A 의 `source_commit` 이 있어야 함(형식만 정의).
- **위험도는 근거 출처를 표시**: plan 이 없으면 텍스트 근거로만 판정하고 부착 지점·실제 삭제/교체·provider 동등성은 '미확정' 으로 남긴다.
- **REVIEW_REQUIRED ≠ 검증 통과**: state.json 의 verification_status 와 계층 표가 기준.
