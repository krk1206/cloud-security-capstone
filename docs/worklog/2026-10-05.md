## 만든 것

1. **AWS 접속 수단 (OIDC)** — `step1-oidc.sh`: IAM OIDC 공급자 `token.actions.githubusercontent.com` + 역할 `github-actions-plan`(권한: `AmazonEC2ReadOnlyAccess`만). 액세스 키를 저장소에 저장하지 않는다. 신뢰 정책은 저장소 `krk1206/cloud-security-capstone`에서 온 토큰만 허용.
2. **워크플로우** `.github/workflows/terraform-plan.yml` — PR에서 바뀐 `infrastructure/` 하위 폴더만 대상. Terraform 1.16.1 고정. V3(fmt/validate)·V4(plan) 중 하나라도 실패하면 체크 실패. `plan.json`·`plan.txt`를 14일 보관 아티팩트로 저장.
3. **provider.tf 수정** — `profile = "capstone"` 고정값을 `var.aws_profile`(기본 null)로 변경. 로컬은 gitignore된 `terraform.tfvars`에 프로필을 넣어 전과 같이 동작, CI는 OIDC 자격증명을 사용.

## 시행착오 — OIDC 토큰의 sub 형식

첫 실행은 `Not authorized to perform sts:AssumeRoleWithWebIdentity`로 실패. 역할·공급자·저장소 이름을 전부 확인해도 정상이어서 토큰을 직접 디코딩해 보니:

    sub = repo:krk1206@254103321/cloud-security-capstone@1351912851:pull_request

GitHub이 소유자와 저장소 이름 뒤에 숫자 ID를 붙여 보낸다. 신뢰 정책의 조건 `repo:krk1206/cloud-security-capstone:*`은 글자가 달라 거절됐다. 조건에 ID 포함 형식을 추가해 해결(`step1b-fix-trust.sh`). ID는 저장소 이름을 바꿔도 변하지 않으므로 이름 기반 조건보다 안전하다.

확인용 워크플로우 `oidc-debug.yml`(토큰 클레임 출력 + STS 직접 호출)은 테스트 브랜치에만 두었고 브랜치 삭제와 함께 제거.
