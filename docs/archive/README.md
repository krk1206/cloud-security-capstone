## B안이 이후 어떻게 바뀌었나

`02-option-B-devsecops.md`는 **선정 시점**의 내용이다. 이후 검토와 실측을 거치면서
연구 대상 자체가 바뀌었을 정도로 크게 달라졌으므로, 두 문서를 같은 계획으로 읽으면 안 된다.

### 연구 대상의 전환

| 항목 | 선정 시점 (B안 원안) | 현재 |
|---|---|---|
| **1차 연구 대상** | **컨테이너 이미지 취약점 (CVE)** | **AWS IaC 설정 오류 (Misconfiguration)** |
| 검사 대상 파일 | Dockerfile / 컨테이너 이미지 | Terraform (HCL) |
| 최종 배포처 | 쿠버네티스 | AWS 샌드박스 (K8s 미사용) |
| 스캐너 | Trivy + Grype | Trivy 단일 (`trivy config`) |
| 판단 기준 | 없음 | CIS AWS Benchmark 중 직접 대응 항목 |

**Vulnerability와 Misconfiguration은 다른 개념이다.** 전자는 소프트웨어 자체의
결함(CVE)이고, 후자는 정상 기능을 잘못 설정해서 생기는 위험이다. 원안은 전자를,
현재는 후자를 다룬다. 컨테이너 CVE는 선택 확장으로 내려갔다.

**전환 이유** — 클라우드 인프라를 주제의 중심에 두기 위해서다. 원안에서 AWS/K8s는
배포처였을 뿐 검사 대상이 아니었고, 그 상태로는 "클라우드 보안 프로젝트"라기 어려웠다.

### 게이팅 설계의 추가와 변경

| 항목 | 선정 시점 | 현재 | 근거 |
|---|---|---|---|
| 게이트 동작 | 취약점 탐지 시 배포 중단(Fail) | 위험도 기반 자율성 3등급 | 전부 차단 / 전부 통과의 이분법을 벗어나기 위함 |
| 확신도 개념 | 없음 | Risk Rubric이 상한 강제, LLM은 하향 제안만 | 이후 추가된 개념 |
| 성공 판정 | 재스캔 통과 | 검증 스택 8계층 | 재스캔만으로는 실효 개선을 보장하지 못함을 실측 |
| AI의 위치 | 시스템의 핵심 | 검증 대상 | 결정론적 검증을 도입할수록 AI 담당 영역이 축소됨 |
| 무인 apply | 언급 없음 | 운영 금지 / 실험 경로 한정 | 자동 처리 시간 측정에 필요. 안전망은 Intent Oracle |
| 필수 유형 | 해당 없음 | 2개 (보안그룹 / IAM) | S3는 수정이 정해져 있어 rule-based가 유리 |
