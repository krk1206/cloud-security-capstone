# 고객 요청서 (가상 · 예제) — 요청 3: 웹 서버 역할 권한 과다 점검 지적 조치

- 보낸 곳: (가상) 3계층 웹 서비스 운영팀 — 이 예제를 위해 만든 가상의 고객입니다
- 보낸 사람: (가상) 운영팀 보안 담당
- 받는 사람: 클라우드 보안 담당 (IaCPatch 를 쓰는 사람)
- 대상: 3계층 웹 서비스 Terraform 코드 (`scenarios/arch/three-tier-team-iam` — 팀 저장소 `infrastructure/three-tier` 사본, 요청 1 을 고친 뒤의 코드)

안녕하세요. 3계층 웹 서비스 운영팀입니다. 지난번 SSH 건(요청 1)은 잘 받았습니다.

이번 점검에서 "웹 서버가 쓰는 IAM 역할이 모든 S3 리소스에 모든 작업(s3:*)을 할 수 있다" 는 지적을 받았습니다.
새 기능을 넣으면서 권한을 넓혀 둔 것 같습니다. 아래 조건을 지켜서 고쳐 주시고, 무엇을 왜 바꿨는지 PR 로 알려 주세요.

## 요청 조건 (꼭 지켜 주세요)

1. 웹 서버 역할은 자산 버킷(assets)의 파일 읽기와 목록 보기만 할 수 있게 해 주세요. 다른 버킷 · 다른 서비스의 권한은 없어야 합니다.
2. 웹 서버는 지금처럼 자산 버킷의 파일을 읽을 수 있어야 합니다. 권한을 줄이다가 서비스가 멈추면 안 됩니다.
3. 지적된 곳 말고는 바꾸지 말아 주세요. 이 역할을 쓸 수 있는 대상(EC2)을 바꾸거나, 새 보안 문제를 만들면 안 됩니다.
4. 무엇이 바뀌는지 먼저 보여 주시고, 저희 담당자가 승인한 뒤에 반영해 주세요.

## 참고

- 웹 서버 역할의 권한은 저희 팀 설계 문서(`docs/architecture/three-tier-design.md` 1.12절 · 2.2절 결정 10)를 따릅니다. ③ 화면 아래 '팀 설계 문서' 에 그 문장을 그대로 옮겨 두었습니다.
- 서버 접속용 SSM 관리형 정책(AmazonSSMManagedInstanceCore)은 설계 문서대로 그대로 둡니다.
- 버킷 이름은 Terraform 이 만들 때 정해집니다 (`bucket_prefix`) — 이름 대신 코드의 `aws_s3_bucket.assets` 로 봐 주세요.
