# 고객 요청서 (가상 · 예제) — 요청 6: 웹 서버 업로드 권한이 S3 전체 작업으로 열림 — 업로드만 되게 요청

- 보낸 곳: (가상) 3계층 웹 서비스 운영팀 — 이 예제를 위해 만든 가상의 고객입니다
- 보낸 사람: (가상) 개발팀 리드
- 받는 사람: 클라우드 보안 담당 (IaCPatch 를 쓰는 사람)
- 대상: 3계층 웹 서비스 Terraform 코드 (`scenarios/arch/three-tier-team-upload` — 팀 저장소 `infrastructure/three-tier` 사본, 앞 요청들을 고친 뒤의 코드)

안녕하세요. 3계층 웹 서비스 운영팀 개발 담당입니다. 지난번 권한 건(요청 3)은 잘 받았습니다.

이번에 '사용자가 올린 이미지를 자산 버킷에 저장' 하는 기능을 붙이면서, 개발자가 웹 서버 역할에 업로드 권한을 넣었는데
S3 의 모든 작업(s3:*)으로 넣어 버려서 점검에서 다시 지적을 받았습니다.

## 요청 조건 (꼭 지켜 주세요)

1. 웹 서버 역할은 자산 버킷(assets)의 파일 읽기 · 목록 보기 · 올리기(업로드)만 할 수 있게 해 주세요. 지우기 · 설정 바꾸기 같은 다른 작업은 없어야 합니다.
2. 웹 서버는 지금처럼 파일을 읽을 수 있어야 하고, 새로 파일을 올릴 수도 있어야 합니다. 권한을 줄이다가 업로드 기능이 멈추면 안 됩니다.
3. 지적된 곳 말고는 바꾸지 말아 주세요. 이 역할을 쓸 수 있는 대상(EC2)을 바꾸거나, 새 보안 문제를 만들면 안 됩니다.
4. 무엇이 바뀌는지 먼저 보여 주시고, 저희 담당자가 승인한 뒤에 반영해 주세요.

## 참고

- 읽기 권한은 팀 설계 문서(1.12절)대로, 업로드는 이번 요청으로 더하는 것입니다. ③ 화면 아래 원문 칸에 두 문장을 그대로 옮겨 두었습니다.
- 버킷 이름은 Terraform 이 만들 때 정해집니다 (`bucket_prefix`) — 이름 대신 코드의 `aws_s3_bucket.assets` 로 봐 주세요.
