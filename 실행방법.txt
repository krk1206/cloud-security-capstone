IaCPatch 실행 방법 (2026-11-07 17차 — 화면 정리: 필요 없는 것 빼기 · 겹친 글자 · 버그 · 프로그램 v0.15.0)

0. 이 묶음에는 IaCPatch.exe 가 들어 있지 않다 — exe 는 윈도우 PC 에서만 만들 수 있어서, 만든 사람이 한 번 빌드해 이 폴더 맨 위에 넣는다.
   - 빌드: 이 폴더 안 packaging\build_exe.bat 더블클릭 (Python 3.10 이상 + 인터넷 필요, 5~10분). 끝나면 이 폴더 맨 위에 IaCPatch.exe 가 생긴다.
   - exe 를 넣은 뒤 폴더째 전달한다. exe 없이도 IaCPatch.bat 로 실행할 수는 있다 (그 PC 에 Python 3.10 이상이 있을 때만).

1. 이 폴더를 통째로 원하는 곳에 둔다 (예: 바탕화면, C:\IaCPatch).
   - IaCPatch.exe 만 따로 빼면 안 된다. exe 가 옆의 policy, scenarios, experiments, tests, scripts 폴더를 읽는다.
   - Program Files 처럼 쓰기가 막힌 곳은 피한다. 실행 기록을 data 폴더에 쓴다.

2. IaCPatch.exe 를 더블클릭한다 → 프로그램 창이 열린다.
   - 서명 안 된 exe 라서 "Windows의 PC 보호" 창이 뜰 수 있다 → "추가 정보" → "실행".
   - 시작 화면 맨 위 '준비 상태' 줄에 "v0.15.0 · 커밋 … · 소스 지문 …" 이 보이면 이 판이 맞다. "exe 가 옆 폴더 코드와 다름" 이 보이면 0번을 다시 한다.

5-2. 15차에서 바뀐 것 — 같은 고객의 요청이 3건
   - 팀 3계층 예제가 '(가상) 3계층 웹 서비스 운영팀' 의 요청 1 · 2 · 3 으로 늘었다 (팀 README 의 시나리오 1 · 2 · 3 을 하나씩).
     요청 1 = Bastion SSH 전체 공개(지난 판과 같음), 요청 2 = 자산 버킷 공개 차단 4개 꺼짐(S3), 요청 3 = 웹 서버 역할이 모든 S3 리소스에 s3:*(IAM).
     세 사본 모두 팀장의 infrastructure/three-tier 사본이고, 원본과 다른 곳은 각 폴더 README 표에 있다.
   - 요청 2 (S3): 찾기만 하고 자동으로 고치지 않는다. 팀 정책 파일(policy/patch_policy.json)의 자동 수정 대상에 S3 공개 차단이 없어서다.
     ② 맨 위 '사람에게 넘김' 칸 = 무엇이 문제(Trivy 4건 · 지금 값) · 왜 자동으로 안 고치나(정책 파일을 그대로 읽음) · 사람이 할 일 · 고친 뒤 확인.
     정책에 넣을지는 팀이 정한다 (넣을 줄은 scenarios/arch/three-tier-team-s3/README.md 마지막 절). 프로그램은 policy 폴더를 바꾸지 않는다.
   - 요청 3 (IAM): ② ~ ⑧ 끝까지 간다. 그림이 '권한 그림' 으로 바뀐다 — 상자 = 역할 · 리소스, 선 = 권한(동작 · 리소스).
     ③ 'IAM 요구사항 v1' = 팀 설계 문서의 웹 서버 권한(assets 버킷 읽기 · 목록)을 옮긴 초안 → 담당자가 확정.
     ⑤ 수정안마다 요구사항 밖 권한은 빨강, 꼭 필요한데 빠진 권한은 빨간 점선. ⑥ 다섯째 질문 = '고객이 허용한 권한만 남았나요?'.
     고친 정책이 버킷 이름(apply 때 정해짐)을 가리키면 plan 에 정책 값이 없어서, 검사(V6)가 코드의 정책 문서를 직접 읽어 비교한다 (화면에 '코드에서 읽음').
     모르는 모양이면 '판정 불가' 로 남기고 통과시키지 않는다.
   - 같이 고친 것: 위험도 근거에 IAM 수정이 '대상 외 종류 +2' 로 잘못 붙던 것(등급은 그대로 MEDIUM) · '사람에게 넘김' 칸의 표가 옆 칸으로 넘치던 것.
   - 검사 · 판정 · 승인 · PR 규칙과 policy 폴더는 그대로다.
