    2 · 수정안
    
        
    수정안을 고르고 검사한다
    
        
    팀이 미리 만든 수정안과, 지금 AI(Claude Code)나 규칙 기반으로 새로 만든 수정안을 같은 검사에 넣는다. 수정안이 맞는지 틀린지는 화면에 미리 적어 두지 않는다.
    
      
    
      
    
      
    
    
    
  
    

  
    
    
    
      
    
        
    3 · 검사 결과

    초록 칸은 Trivy가 다시 검사한 결과, 파란 칸은 설계도와 비교한 결과다. 줄을 누르면 4번에서 그 수정안의 위험도와 결정을 본다.

    4 · 결정
    
        
    통과한 수정안은 위험도를 보고 사람이 정한다
    
        
    위험도는 "이 변경이 잘못되면 영향이 얼마나 넓은가"다. 검사 통과와 따로 매기고, Trivy 심각도와도 다르다. 적용(apply)은 항상 사람이 승인한 뒤에 한다.
    
      
    
      
    
        
    3단계 표에서 수정안 줄을 누르면 여기에 나온다.
    
        
    
          
    등급점수다음 처리
    
          
            
    LOW0~2점사람 1명이 바뀐 내용과 검사 표를 보고 진행 (수정 이유가 빠졌으면 MEDIUM처럼 승인 필요)
    
            
    MEDIUM3~5점, IAM 변경은 최소 이 등급승인자가 근거를 보고 승인해야 진행
    
            
    HIGH6점 이상, 또는 강제 조건수정 반영 금지, 보고서만
    
              
        
    
      
    
      
    
        사람 승인 (이 화면)다음
        PR다음
        ② 임시 AWS 환경에서 V7 · V8다음
        PR 병합 · ③ 상시 환경 반영 (사람 승인)
      
    
      
    이 다음은 GitHub Actions 파이프라인이다. 지금 ② ③ 에 연결된 대상은 infrastructure/sg-baseline 하나이고, 위 예제(팀 3계층)는 아직 연결되지 않았다.
