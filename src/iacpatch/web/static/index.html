IACPATCH · 브라우저 화면

AI가 생성한 테라폼 보안 패치의 실효성 검증 자동화 구현

Trivy 가 통과시킨 패치를 그대로 믿지 않는다 — 검증 계층 + 위험도 기준표가 후보마다 '사람이 어떤 검토를 해야 하나' 를 정한다. 이 화면은 LLM API·AWS·git push·terraform apply 를 절대 부르지 않는다.

불러오는 중…

4주차 목표 — "목업 데이터로 High/Medium/Low 가 올바르게 분류되고, 상한 강제가 동작한다"

위험도는 코드가 정한다(plan 의 사실만 입력). LLM 은 등급을 낮추는 제안만 할 수 있고, 상한을 넘는 제안은 무시하고 기록한다. 아래 세 표가 그 세 문장을 각각 증명한다.

① 위험도 기준표

원본은 policy/risk_rubric.json (사람이 고친다). 점수 합계 ≤ 2 → LOW(자율성 상한 HIGH), ≤ 5 → MEDIUM(상한 MEDIUM), 그 위 → HIGH(상한 LOW). 아래 '무조건 HIGH' 조건은 점수와 무관.

            ④ 기준표 계산기 (목업 입력)

            체크·숫자를 바꾸면 진짜 score_risk() 가 점수와 등급을 낸다. "이 조합이면 왜 MEDIUM 이지?" 를 요인별 점수로 본다.

            ⑤ 게이트 데모 — LLM 제안이 상한을 넘으면?

            코드가 정한 위험도와 LLM 제안을 넣으면 게이트가 최종 자율성과 동작을 정한다. 이유 문장은 코드가 낸 것 그대로.

            5주차 목표 — 시나리오 → 패치 후보 → 검증(V1~V6) → 위험도 → 검토 수준 → PR 미리보기

            한 후보를 골라 실제 검토 흐름을 돌린다. trivy/terraform 이 tools\ 에 있으면 V1~V4 도 실행하고, 없으면 그 계층은 NOT_RUN 으로 남는다(가짜 PASS 없음). AWS·LLM 은 부르지 않는다. PR 은 미리보기까지만(브랜치·제목·명령) — push 는 사람이 한다.

            대상 finding 이 가리키는 .tf 파일의 전체 내용을 붙여넣는다 (원본에서 고친 버전). 출처는 기록에 '붙여넣기' 로 남는다 — LLM 출력이면 그렇게 적어라.
